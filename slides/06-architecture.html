The Three-Tier Block Diagram

Three tiers, loosely coupled.

If the backend dies, verification still works. If Pinata is down, old certificates still verify. The chain is the only mandatory part — the rest is orchestration.

I.
The Browser.
Where roles meet code.

Three role-specific surfaces — institution issuance, student portfolio, public verifier. Two are wallet-gated. The third (the verifier) deliberately is not. EIP-6963 multi-wallet discovery defeats the OKX/MetaMask injection conflict.

Two of three pages need a wallet. The verifier deliberately doesn’t.
Next.js 14 · React 18 · Ethers v6
MetaMask · EIP-6963
II.
The Backend.
Convenience, not authority.

Six Express routes on port 8787. SQLite (WAL mode) holds an event-log table — for analytics only. The Pinata JWT lives server-side and never touches the browser. Take this layer offline and verification still works.

Convenience layer. Take it offline and verification still works.
Express 4 · better-sqlite3
Pinata V3 proxy · multer
III.
The Chain.
The source of truth.

A single Solidity 0.8.28 contract on Sepolia at 0x14Cf…64d5. It stores the Certificate struct + the keccak256 anchor. IPFS holds the file itself, content-addressed. Together they constitute the full proof.

The contract is the source of truth. Everything above is orchestration.
Solidity 0.8.28 · OpenZeppelin v5
Sepolia · Pinata IPFS
Issue Flow Browser → Backend → Pinata → MetaMask → Sepolia → Browser
Verify Flow Browser → Sepolia (read-only RPC) → Browser — no backend, no wallet, no signature.
